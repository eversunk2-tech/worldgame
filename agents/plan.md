## 에셋 조사 (Plan이 반드시 수행)
WebFetch/WebSearch로 다음을 확인해 spec에 표로 정리한다: 각 팩의 공식 페이지 URL, 실제 zip 다운로드 URL(찾을 수 있으면), 파일 크기, 타일 크기(16px 예상), 시트 파일명과 간격(margin/spacing), 포함 내용 중 이 게임에 쓸 것(지면·도로·물·건물·나무·가구·캐릭터 파츠), 라이선스 원문 링크.
- **특히 Roguelike Characters에 4방향 걷기 애니메이션 프레임이 있는지 확인**한다. 없다면 (a) 코드로 만드는 걷기 연출(다리 교차 2프레임 합성 + 좌우 반전 + 상하 이동 바운스)과 (b) 4방향 걷기 프레임이 있는 다른 CC0 팩(예: itch.io의 Ninja Adventure Asset Pack — CC0 여부·URL·크기 확인) 두 안을 비교해 추천안을 정하고 "사용자 확인 필요"에 올린다.
- Kenney 시트에는 타일 이름이 없다. Build가 시트를 보고 인덱스를 찾아야 하므로, spec에 **타일 인덱스 조사 도구**(개발용 HTML 페이지: 시트를 3~4배 확대해 격자와 인덱스 번호를 겹쳐 그림, 브라우저 도구로 확인)와 **의미 타일 목록**(예: grass, grass_flower, road_h, road_v, road_cross, sidewalk, water, water_edge_n…, building_wall, roof_red, door, window, tree_round, tree_pine, bench, lamp, sign, fence, sand, palm, cactus, snow… 도시 6곳을 그리는 데 필요한 것 전부)을 정의한다. Build는 이 목록의 각 항목을 시트 인덱스에 매핑한 `tileAtlas.ts`를 만든다.
- 랜드마크(에펠탑·피라미드·자유의 여신상·오페라하우스·예수상·남산타워 등)는 팩에 없을 가능성이 크다. 타일 조합 또는 Canvas로 그린 48~96px 스프라이트로 만드는 방식을 정한다.
- 에셋 저장 위치와 git 포함 여부: `public/assets/vendor/<pack>/` 에 필요한 시트만 두고 각 팩의 라이선스 파일을 함께 둔다. 크기가 작으면 git에 포함(clone만으로 실행 가능)하는 것을 권장. 다운로드·압축 해제·필요 파일 추출을 하는 `scripts/fetch-assets.mjs`(Node 내장 fetch + unzip 방법 명시, 승인 목록 외 URL 금지)를 설계한다.

## 미니게임 4종 설계 (기존 플러그인 인터페이스 `src/shared/logic/minigame/*` 확장)
각 게임에 대해: 데이터 스키마(shared/content), 순수 로직(shared/logic, 시드 기반, 채점·합격 기준), 단위 테스트 목록, Phaser 씬 UI(마우스+키보드 모두), 미션 연결 방식, 포인트.
- 짝맞추기: 4×3 또는 4×4 카드, 나라–수도·지형–설명·문화–나라 등 짝. 시도 횟수 기준 별점.
- 지도 위치 찾기: 세계지도 위 목표(도시·대륙·대양) 5문항, 허용 반경, 점수.
- 순서 맞추기: 3~5개 항목 정렬(시차 순, 위도 순, 인구 순, 역사 순서 등). 마우스 드래그와 키보드(선택 후 ←/→) 모두.
- 빈칸 채우기: 문장 1개에 빈칸 1~2개, 보기 4개.
- 각 도시의 미션은 최소 3종 이상의 서로 다른 미니게임을 사용하도록 배분.

## 구현 단계 (Build를 3단계로 나누고 단계마다 Review·커밋)
spec의 구현 순서는 아래 3단계로 나누고, 단계별로 **수정 파일 소유권**(어느 단계가 어떤 파일을 만들고 고치는지)을 표로 명시해 충돌을 막는다. 각 단계에 완료 기준과 Review 체크리스트를 둔다.
- **Stage A — 에셋 파이프라인 + 그래픽 업그레이드 + ZEP 요소**: 다운로드 스크립트, 타일 인덱스 도구, tileAtlas, 캐릭터 시스템, 서울·파리 맵 재작성, 세계지도, UI 폰트·패널, 이름표·말풍선·이모지·미니맵·BGM·SFX.

- **Stage C — 도시 4곳**: 콘텐츠·맵·NPC·몬스터·미션·해금·세계지도 갱신·저장 v3.
